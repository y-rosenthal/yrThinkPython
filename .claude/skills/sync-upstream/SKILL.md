# Sync with upstream

Remotes: `origin` = y-rosenthal/yrThinkPython (this fork, branch `v3`); `upstream` =
AllenDowney/ThinkPython. The fork's own changes are the commits after the fork point; most
of them touch `jb/`, `README.md`, `.github/` and course edits inside `chapters/`.

## 1. See what changed upstream

```bash
git fetch upstream
git log --oneline HEAD..upstream/v3            # commits we do not have
git diff --stat HEAD...upstream/v3             # files they touched
git diff --stat upstream/v3...HEAD             # files the fork changed (potential conflicts)
```

For a cell-level view of what the fork has changed, use the `upstream-diff` skill.
Summarise this for the user before merging: which chapters upstream changed, and whether any
of them were also edited in the fork. Upstream commit messages are usually just "Updating the
notebooks", so look at the diff stat, not the messages.

## 2. Merge (only when asked)

```bash
git merge upstream/v3
```

Notebook conflicts are JSON and rarely resolvable line by line. Rules:

- Chapter the fork never edited (not in `git diff --stat upstream/v3...HEAD`): take upstream,
  `git checkout --theirs chapters/chapNN.ipynb && git add chapters/chapNN.ipynb`.
- Chapter the fork did edit: keep ours (`--ours`), then re-apply upstream's change by hand using
  `nb_cells.py` (notebook-conventions skill) to locate cells. Show the user upstream's diff
  for that chapter so they can decide.
- `blank/*.ipynb` are upstream-maintained; take theirs, then regenerate with `make-blank` if
  the fork regenerates blank notebooks from its own chapters.
- `jb/index.md`, `jb/blank.md`, `jb/_config.yml`, `README.md`, `.github/`: keep ours. Upstream's
  versions point at AllenDowney URLs and lack the deploy workflow.
- `*.zip` files: take theirs (binary; regenerated by upstream's build scripts).
- `thinkpython.py`, `diagram.py`, `structshape.py`: take theirs unless the fork changed them.

If a chapter conflict is a correction the fork already reported upstream (see
`contribute-upstream`), take upstream's version: it is his wording, and it ends the divergence.

## 3. After the merge

1. `python3 ${CLAUDE_PROJECT_DIR}/.claude/skills/check-notebooks/check_notebooks.py` must print `OK`
   (a bad conflict resolution shows up as invalid JSON here).
2. Build locally with the `build-book` skill; check `_toc.yml` still lists every chapter.
3. Do not push; report the merge summary and let the user decide to deploy (`deploy-book` skill).
