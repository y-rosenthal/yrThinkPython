# research:prototype

I built the proposed layout on a copy of the repo and tested it. It works in nbclient's "Run all" stand-in, in JupyterLab and on the website. Nothing under /home/user/yrThinkPython was changed, and git status there is clean.

On why the 3rd and 4th workers failed: I don't have their logs, so these are likely causes, not confirmed ones. I hit three environment traps myself while doing this task:
- The task says to copy with rsync, but rsync isn't installed in this container. My own first command failed with "rsync: command not found" (I used tar instead).
- build_book.sh and review.sh find the repo root with `git rev-parse`, which fails in a copy that has no .git folder.
- The Playwright in the other worker's venv (scratchpad/ultra/jupyter-facts/venv-lab) looks for a browser build that isn't installed. It only works if you point it at /opt/pw-browsers/chromium-1194/chrome-linux/chrome.

What I built: scratchpad/ultra/proto/scripts/convert.py turns a page into the new layout. Each question's code moves into a ```python block in the question text. Then comes a '#### Answer' heading saved collapsed for both Colab and JupyterLab. Under it go the old explanation (expected output, turtle picture) and a code cell that runs exactly the question's code. When that code raises, the cell wraps it in run_code("""..."""), and run_code is now `get_ipython().run_cell(code)`. Cells like "Run this cell to define countdown_by_two" stay as runnable cells.

I converted all six pages, not just chap05. Results:
- **Run all reaches the end on all six pages.** I simulated it with nbclient set to stop on errors and to ignore the raises-exception tags, as Colab does. No answer output is visible afterwards; the only visible output is chap07's setup line "Downloaded words.txt". The current chap05 stops at Question 8 with 7 answers already showing. The new layout also reached the end with the IPython 7.34 / ipykernel 6.17 versions I believe Colab runs.
- **JupyterLab 4.6.4:** the page opens with every Answer collapsed. "Run All Cells" runs the hidden cells and their outputs stay hidden. Expanding an Answer shows the real error messages.
- **Website:** I changed a copy of prep_notebooks.py so each Answer section becomes one collapsed "Answer" box. The Answer code cells are left out (the question's code is just above). There are no "Answer" entries in the right-hand contents list and no new build warnings. I looked at screenshots of Questions 8, 14 and 17.
- **Checks:** I adapted copies of check_review.py and turtle_images.py. The check passes on all six pages and caught all 10 deliberately broken copies I tried. It still runs every standalone-.py, exact-output, header, two-example and two-correct-call check, and adds checks for "Run all reaches the end", "nothing visible outside an Answer", "Answers saved collapsed", and "the Answer's code is exactly the question's code". The adapted picture tool redraws all chap05 and chap04 pictures byte for byte.

Problems found:
1. **Shift+Enter gives answers away in JupyterLab.** A student stepping through the page with Shift+Enter walks into each collapsed Answer and expands it; the screenshot shows the whole Answer and its output. The current details-based answers don't do this. I couldn't test Colab.
2. **The last Answer swallows the credit line.** A collapsed heading hides everything up to the next heading of the same or higher level, so the closing credits would be hidden inside Question 17's Answer. I fixed it by adding a "## Credits" heading, which adds one entry to the contents list.
3. **The Answer code must be byte-identical to the question's code.** I first added a comment line to each Answer cell. That shifted the line number in chap07 Q14's doctest report from line 9 to line 10, and the exact-output check failed.
4. **Guessing which code blocks are "the question's code" fails on refactor questions** (chap03 Q12; chap04 Q11, 17, 18, 19; chap06 Q12). The rule "a question with a '# Your code here' cell has no Answer code cell" works on all six pages. An explicit marker would be safer.
5. **chap06's setup cell has no run_code**, but it is now needed on every page.
6. **The current tools break on the new layout.** check_review.py reports 18 problems on chap05. Worse, it silently skips the standalone-.py check for write-code answers because it no longer finds them. turtle_images.py can't find the code for Question 17's picture.

On not typing code twice:
- **A (one source, Answer cell generated):** works. When I edited Question 8 Part b in the question text, the check failed. The prototype sync script then regenerated the Answer cells and the check passed. Pyright finds nothing in the Answer cells. For a new question that raises at run time (not a syntax error), the author has to add the run_code wrapper once; the check says so.
- **B (code in a string variable):** runs to the end and Pyright finds nothing. But the question code shows in one colour, and the website shows `q8a = """`.
- **C' (%%question cell magic):** runs to the end, and JupyterLab and the website colour the code body as Python. But plain Pyright flags the magic line, the hidden syntax errors themselves, and "q8a is not defined" in the Answer cells. Whether Colab's editor does the same is unknown.

I recommend A.

The main risks are still untested because Colab can't be reached from here. Someone needs to open the prototype notebook in Colab and check four things: does Run all go past an error shown this way, does it run the collapsed cells while keeping them hidden, does Shift+Enter expand Answers, and are the Answers collapsed on open.

## Open questions

- Colab: does Runtime > Run all stop only when a cell's reply status is 'error', or also when a cell sends an error message without failing? Both run_code variants send an error message while the cell's status stays 'ok'. If Colab stops on the message, run_code would have to print the formatted traceback to stderr instead; a stderr variant I tested also reached the end under nbclient.
- Colab: does Run all run cells inside collapsed sections without expanding them or scrolling to them? JupyterLab does (verified).
- Colab: does stepping with Shift+Enter (or Ctrl+Enter then moving on) expand collapsed Answer sections, as JupyterLab does (verified)?
- Colab: does it collapse the headings listed in collapsed_sections when the notebook is opened from GitHub, with 8-hex ids set as both the top-level id and metadata.id? Strong evidence says yes; no direct test.
- Colab: does its editor underline syntax errors inside the body of a %%question cell? This decides whether option C' is usable at all.
- Is it acceptable that Colab's and JupyterLab's table-of-contents sidebars will list 17 'Answer' entries per page (believed, not checked)?
- Design choice: one collapsed section per question (explanation and live output together), or two ('Run the code' and 'Explanation') so students can check by running before reading the explanation?
- For option A, should the code to run be marked explicitly (for example in cell metadata or the code fence's info string) instead of using the rule 'questions with # Your code here run nothing'?
